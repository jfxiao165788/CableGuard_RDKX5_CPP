# Cable_Cpp

This directory is the C++ deployment path for the RDK X5 cable inspection
pipeline. It does not modify the existing Python ROS2 packages.

## Migration scope (important)

This is a partial C++ port, not a conversion of every Python tool in the
repository. The C++ implementation currently covers the visual cable-detection
pipeline: cable-band masking, letterbox preprocessing, detection postprocessing
and NMS, ROI refinement, center confirmation, JSON/annotation output, a ROS2
image node, and a synthetic CPU benchmark.

The following remain Python-only and are intentionally outside this package:

- camera and infrared ROS2 nodes, image saving, motor control, and the Flask web
  control service;
- AD5933 driver/calibration/impedance analysis;
- DINOv3/YOLO training, ONNX export, BPU mapper, and model evaluation tools;
- `python/benchmark_python.py`, which is retained as the reference benchmark.

The `HorizonBpuBackend` is currently an SDK boundary/placeholder. On the PC it
fails closed; it does not execute a `.bin` model. A real X5 deployment still
requires wiring the exact `hb_dnn` API provided by the target board image.

Directories named `build*` are generated by CMake during local builds and are
not source code. They are ignored by this package and should not be uploaded.

## What is implemented

- C++17 OpenCV implementation of the existing cable-band mask, letterbox
  preprocessing, YOLO-style decode/NMS interface, cable-mask filtering, ROI
  blackhat/gradient/contrast refinement, center confirmation, JSON output and
  annotated images.
- ROS2 `cable_detection_node` with the same topics as the Python detector:
  `/camera/image_raw`, `/detection/results`, `/detection/annotated_image`,
  `/detection/cable_mask`, `/detection/defect_detected` and
  `/detection/defect_in_center`.
- `SyntheticBackend` for deterministic PC tests. `HorizonBpuBackend` is the
  board adapter boundary. The current PC has no Horizon SDK headers, so the
  checked-in adapter fails closed instead of pretending that a `.bin` was
  executed. On the board, wire the exact `hb_dnn.h` API from the installed X5
  SDK in `src/bpu_backend.cpp` and build with `-DCABLE_ENABLE_HORIZON_BPU=ON`.
- Preallocated/reused detector state, configurable inference frame skipping,
  OpenCV thread control and Linux CPU affinity. These reduce Python object
  creation and callback overhead while avoiding CPU oversubscription around the
  BPU runtime.

## PC build and benchmark

```bash
cd /home/speedbot/csu/xjf/cable1/Cable_Cpp
cmake -S . -B build -DCABLE_BUILD_ROS2=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
./build/cable_benchmark --frames 120 --warmup 10 --interval 3 \
  --json benchmark_cpp.json --save-image benchmark_cpp.jpg
python3 python/benchmark_python.py --frames 120 --warmup 10 \
  --json benchmark_python.json
```

Or run `scripts/run_benchmark.sh`. The benchmark uses the same deterministic
synthetic 640x480 scene for both implementations. It measures CPU preprocessing,
mask extraction, simulated coarse detection and ROI refinement. It does not
claim to measure a real BPU `.bin` because the current PC has neither the model
file nor `hobot_dnn`; the ROS2 board run uses the supplied BPU adapter.

The local 120-frame run on this machine measured:

| implementation | mean per frame | p95 | throughput |
| --- | ---: | ---: | ---: |
| Python/OpenCV reference | 10.93 ms | 11.80 ms | 91.5 FPS |
| C++17/OpenCV optimized | 2.52 ms | 7.48 ms | 396.7 FPS |

The comparison uses the same synthetic CPU backend and `inference_interval=3`;
it is a CPU pipeline comparison, not a claim about the eventual BPU inference
latency on X5.

## RDK X5 build

After sourcing ROS2 Humble and placing `current.bin` at the configured path:

```bash
cd /home/sunrise/cable1/Cable_Cpp
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCABLE_BUILD_ROS2=ON \
  -DCABLE_ENABLE_HORIZON_BPU=ON
cmake --build build -j$(nproc)
```

Use `scripts/rdk_x5_run.sh` after verifying the CPU numbering with `lscpu -e`.
The default affinity `4,5,6,7` is a starting point, not a board invariant.
The BPU adapter must be matched to the exact SDK image installed on the board;
the rest of the detector and ROS2 contract is independent of that SDK detail.
The ROS2 node refuses to start with a model path until the Horizon adapter is
available. `allow_synthetic_backend:=true` is reserved for development tests
and must not be used for inspection deployment.

## Performance knobs

- `inference_interval=3` reuses the last detection for two camera frames, as in
  the current Python node. Set it to `1` when every frame must be inferred.
- Keep `opencv_threads=1` when the BPU runtime already owns worker threads.
- Use `cpu_affinity`/`taskset` to reserve a big-core cluster for the detector.
- Build in `Release` so the compiler enables `-O3`, fast math and inlining.
